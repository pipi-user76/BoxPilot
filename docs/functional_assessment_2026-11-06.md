# BoxPilot 功能评估与进阶规划

- 评估日期：2026-11-06
- 当前阶段：MVP 可演示版
- 结论：四个核心任务模板已形成执行闭环，适合本地演示和课程项目迭代；尚不适合直接暴露到公网或执行不可信代码。

## 1. 当前功能评估

| 能力 | 当前状态 | 评价 |
|---|---|---|
| 任务创建与查询 | 已实现 | 支持普通 JSON 任务和 CSV multipart 上传 |
| 任务状态机 | 已实现 | PENDING、RUNNING、SUCCESS、FAILED、TIMEOUT |
| 步骤记录 | 已实现 | 每步记录状态、耗时、输出摘要和错误 |
| 沙箱调用 | 已实现 | Shell、文件、浏览器、文本和截图统一封装 |
| 网页资料整理 | 已实现 | 输出文本、截图和元数据报告 |
| CSV 数据分析 | 已实现 | 行列、缺失值、重复行和数值统计 |
| 仓库体检 | 已实现 | 白名单仓库、固定命令和离线示例 |
| 网页验收 | 已实现 | 明确返回标题匹配或不匹配 |
| Web 工作台 | 已实现 | 任务列表、轮询、详情、业务结论和产物下载 |
| 产物管理 | 已实现 | 任务独立目录、非空校验和受控下载 |
| 持久化 | 未完成 | 当前为内存存储，后端重启后记录丢失 |
| 身份认证 | 未实现 | 只适合本地单用户环境 |

## 2. 核心优点

1. 模板执行是确定性的。任务只按固定步骤运行，不依赖模型自由规划，演示结果容易复现。
2. 任务状态和业务结论分离。网页验收即使标题不匹配，任务执行仍是 `SUCCESS`，但界面明确显示“标题不匹配”。
3. 过程可观察。每个步骤都有中文名称、状态、输出摘要和耗时。
4. 产物有校验。空文件不会登记为有效产物，界面提供统一下载入口。
5. 断网演示能力较完整。网页整理和网页验收可以访问本地页面，仓库体检可以使用 `demo://python`。
6. 页面字段与任务类型联动，创建入口已经覆盖四个模板。

## 3. 当前局限

### 3.1 工程能力

- 任务、步骤和产物仍保存在内存中，服务重启后数据丢失。
- 任务一旦开始，没有取消、重试和超时后的强制清理入口。
- 所有任务串行执行，虽然避免了共享浏览器冲突，但并发能力有限。
- 缺少结构化日志、请求追踪号和指标统计，问题定位主要依赖终端日志。
- 页面只进行轮询，没有进度推送或通知。

### 3.2 安全性

- 系统是可信本地单用户模型，没有登录、权限和租户隔离。
- Shell 黑名单只能阻挡明显危险命令，不能替代容器层面的强制隔离。
- 仓库体检会执行仓库中的测试代码，目前只能信任白名单仓库。
- 没有网络出口白名单、CPU/内存配额或每任务独立容器。

### 3.3 功能深度

- 网页资料整理提取的是页面可见文本，包含导航和界面文字，尚未做正文提取和去噪。
- 截图当前是视口截图，长页面需要整页截图或分段截图。
- CSV 分析使用标准库，缺少图表、异常值识别、数据类型推断增强和大文件流式处理。
- 仓库体检只支持固定 Python/Node 测试命令，无法适配所有项目。
- 公开 GitHub 仓库在当前沙箱网络下可能遭遇 TLS 失败，离线示例是主要演示方式。
- 没有 LLM 摘要、页面问答或报告生成能力。

## 4. 内部成熟度评分

以下评分用于项目内部判断，不代表生产环境认证。

| 维度 | 分数 | 说明 |
|---|---:|---|
| 演示可用性 | 8/10 | 四个模板均可运行，本地页面可演示 |
| 功能完整性 | 7/10 | 核心闭环完整，持久化和运维能力不足 |
| 稳定性 | 7/10 | 有测试和错误处理，但并发和重启恢复有限 |
| 安全性 | 5/10 | 有基础边界，但没有强隔离和身份认证 |
| 可扩展性 | 7/10 | 模板与沙箱接口清晰，新增模板成本可控 |
| 可观测性 | 5/10 | 有步骤记录，但缺少统一日志和指标 |

## 5. 进阶功能建议

> 2026-11-07 更新：P0 第 2、4 项与 P1 第 1、2、3 项已完成，结构化日志、取消/重试、Readability 正文提取、整页截图、预览、搜索分页和批量清理均已落地。SQLite 持久化仍待接入，目标为 `tasks`、`steps`、`artifacts` 三张业务表，外加可选 `task_events` 事件表。

### P0：先完成可交付基础

1. 接入 SQLite `tasks`、`steps`、`artifacts` 三张业务表（及可选 `task_events`），保证服务重启后记录仍可查询。
2. 增加任务事件表或结构化日志，记录状态迁移、错误码和耗时。
3. 建立 10 至 15 个端到端用例，形成成功率和失败原因统计。
4. 增加任务取消和失败重试，区分用户取消、超时和系统异常。

### P1：提升产品可用性

1. 网页整理改用 Readability 或 Markdown 提取，减少导航和脚本噪声。
2. 支持整页截图和下载前预览，CSV 结果增加图表和列级可视化。
3. 增加任务筛选、分页、搜索、批量清理和产物预览。
4. 为模板参数增加配置化校验，避免前端和后端各维护一套规则。
5. 增加离线演示站点和更丰富的 CSV、仓库样例。

### P2：增强平台能力

1. 使用每任务独立沙箱或临时容器，替代当前共享容器。
2. 增加网络出口策略、资源配额和容器级只读文件系统。
3. 增加登录、会话、用户任务隔离和操作审计。
4. 使用任务队列和 worker，支持并发、重试、取消与恢复。
5. 接入结构化监控和告警，记录任务成功率、耗时和沙箱故障率。

### P3：智能化能力

1. 网页整理增加可选 LLM 摘要，失败时自动退回正文摘录。
2. 根据任务结果生成自然语言验收报告和问题定位建议。
3. 允许模型建议下一步操作，但执行必须经过固定模板和人工确认。
4. 对历史任务做失败聚类和修复建议，而不是让模型自由执行 Shell。

## 6. 推荐迭代顺序

1. SQLite 持久化和重启恢复。
2. 统一端到端测试集与可观测日志。
3. 网页正文提取、整页截图和 CSV 可视化。
4. 任务取消、重试和并发队列。
5. 独立沙箱隔离、认证和网络安全策略。
6. 可选 LLM 摘要与报告增强。

当前最重要的不是继续增加模板，而是完成数据持久化、测试统计和失败可观测性，使现有四个模板具备稳定演示和结题交付条件。
